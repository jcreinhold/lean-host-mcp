# Durable native lifecycle evidence, bounded design (draft for independent review)

Scope: new generic writer and external-reader lifetimes only. The private 8aeb25b pre-dispatch classification repair remains a separate, undeployed change. No historical unknown is rewritten; missing old bindings/receipts remain missing. No live deployment, worker retirement, drains, proof inputs, capacity/deadline settings or Mathlib builds are authorized by this work.

## Ownership and dimensions

The existing actual-child owner, writer helper, native guardian, private process group and inherited lock descriptors remain the only execution/custody owners. Evidence files are observations, not a queue, process registry for signalling, capacity store, lease or permission to replay. Retained dimensions are separate: immutable intent/source binding; preparation; target GO authorization; actual target spawn; semantic result; declared helper-held custody release; complete owned-group closure; actual helper/child reap. Absence, EOF, elapsed time, idle state and missing PIDs prove none of these.

## Durable identity before spawn

Use a small shared lean-toolchain native-attempt evidence module consumed by host and Rust writer clients, with a matching Python evidence adapter. A creator allocates a fresh random attempt identity in a private canonical namespace OUTSIDE the existing worker ownership registry (whose scanner rejects foreign entries), exclusively creates and syncs its immutable manifest and parent directory BEFORE any helper spawn. The manifest binds role, source/intent digest, configured helper identity and ownership namespace. An opaque handle (directory, fresh identity, manifest digest) survives every exception and partial/lost first reply. Original handles open existing attempts only; recovery never creates one. Reused identities, changed manifests and aliases refuse. Actual helper identity (PID, birth, session) is independently synced by H BEFORE lock admission. A helper must exclusively claim its one attempt and cannot reuse a previously claimed handle.

Filesystem authentication is the existing local trusted-user/private-directory contract plus exact native-child/generation identity, unpredictable attempt nonce and immutable intent digest. This does not authenticate against malicious code running as the same OS user, which already controls the helper executable and lock namespace. Payload-private environment and control descriptors are stripped before target exec. No claim rests on a PID/path without its bound native identity.

## Publication and bounded retention

Fixed-version, bounded regular-file records, no-follow opens, canonical private directories, exclusive atomic publication, file and directory fsync. Reject FIFOs/devices/symlinks/oversize or malformed records without blocking on their content. One attempt has a fixed maximum of64 writer stages and a fixed bounded record vocabulary; a store has a bounded count. Full retention refuses BEFORE helper spawn. Unresolved attempts are never silently evicted or reopened. Only explicitly closed/reaped terminal evidence for which every authorized late publisher is finished can expire after the documented retention interval; late publication never recreates an expired path; pruning never interprets process absence. Recovery reads only the exact handle and checks manifest/role/helper/stage bindings, never finds a current project row as a substitute.

Pre-spawn persistence failure means no helper. Post-spawn identity/evidence failure seals further dispatch, closes control and invokes the existing owned cleanup; no fallback. Publication failure is reported separately and cannot turn missing evidence into success. Filesystem/kernel stalls still have no universal wall-time guarantee.

## Writer evidence

H publishes a bound actual-helper identity before admission, acquired-domain and asset identity after admission, and immutable per-stage intent before spawning its blocked wrapper. All existing lock/group records still sync before GO. Stage GO-attempt evidence is durable before the first possible GO byte. Any attempted/partial GO with missing actual target receipt stays uncertain. The existing writer started frame observes a blocked wrapper/GO authorization, not proof that the final exec/body ran. No target-started claim is minted from that frame. Stopped-stage evidence is synced before emitting the wire stopped reply, preserving physical closure even when the response is lost. No semantic success is inferred from stopped/reaped evidence.

After dispatch is irrevocably sealed and every actual command group has closed, an outer terminal path explicitly drops owned lock files, loans and writer-demand guards before publishing helper-scoped custody release. Borrowed mode explicitly records unaccounted inherited aliases and does NOT claim full helper custody release merely because duplicate Files dropped. Existing SDK borrowed descriptors remain close-only; no unsafe ownership transfer is introduced. Caller/other-process aliases are outside a helper-scoped receipt. Actual helper reap can settle that helper's descriptor table, but cannot prove a descendant group closed if H died after GO.

## Actual-child late reaping

Extend existing Rust/Python actual-child wait owners with an optional bound evidence sink, reserved before spawn. After an actual wait succeeds, atomically publish its identity-bound helper-exit/reap observation, even when the original waiter has timed out. Failed wait authority or failed publication remains unknown. Never signal a serialized PID during recovery. H's own custody-closed record is independent, so graceful controller loss can leave useful scoped release evidence without pretending H reaped itself. Simultaneous controller/helper loss can prevent both publications; old/new missing receipts then remain unknown and existing OS/group fences alone protect future admission.

## Native-reader post-ACK launch boundary

The existing guardian ACK permits bootstrap/preparation and is NOT target GO. Add one mandatory private bootstrap Ready->GO barrier after complete read-union/guardian loan admission and staged stdin validation, before payload spawn. Bootstrap readiness is bound to the accepted actual generation/owner and immutable command/input intent. The parent persists possible-GO intent BEFORE writing the first GO byte over the actual child's private stdin. Cancel/deadline/caller loss that wins before ANY GO attempt seals dispatch and can publish a scoped target-not-dispatched observation even when preparation/custody closure is unresolved. Any GO attempt without a bound launch/terminal witness remains targetunknown. Actual-spawn evidence is distinct from GO authorization. Child closes/seals the one-shot channel before returning a prebody refusal; late/buffered GO cannot restart it. Existing cancellation/absolute deadlines and guardian/group cleanup remain authoritative. Durable closure evidence may arrive after the original response, but missing evidence never becomes false/true by inference.

## Compatibility and rollout

Advertise a generic native-attempt-evidence-v1/reader-launch-boundary-v1 capability through pure discovery and loaded native compatibility. New clients require the capability before active use; no fallback after possible submission. Older wire records remain readable with absent evidence interpreted as unavailable. New optional evidence fields are strictly validated; no proof-repo special cases, synthetic MCP tickets or SQL capacity rows. SDK and Python adoption must be matched to the privately frozen host image. Python source files are active verification inputs, so stage adapter changes/tests under /tmp until the repo owner supplies a safe original-file handoff/window. Do not edit untracked existing owned_writer/owned_reader tests.
